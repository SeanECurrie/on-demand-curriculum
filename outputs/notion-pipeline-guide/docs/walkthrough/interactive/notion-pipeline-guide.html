Overview

Notion Pipeline

A live pipeline visualization layer for your job search. Built 2026-03-19 via the hosted Notion MCP (claude.ai Notion, OAuth).

Three interconnected databases tracking target companies, contacts at those companies, and outreach actions you’ve taken. The engine’s markdown files remain the source of truth for deep research, positioning, evidence atoms, and resumes. Notion is where you check your pipeline daily, see what needs attention, and update status on the go.

Markdown — Filing Cabinet
Source of truth. Deep research profiles, evidence atoms, positioning documents, resumes, and audit logs. The permanent record.
Notion — Whiteboard
Daily dashboard. Pipeline status, what needs attention, temperature checks, quick notes. The operational view.
Sync Direction
Engine syncs from markdown → Notion, not the reverse — except for lightweight operator updates (temperature, notes, stage drags) which are reconciled at session start. When they disagree, markdown wins.

Databases

How the Databases Connect

  • Each Pipeline entry can have multiple Contacts (the “Contacts” column shows linked people, “Contact Count” rollup counts them).
  • Each Contact can be linked to one or more Pipeline entries (they might know people at multiple target companies).
  • Each Outreach action links to one Contact (who you messaged).
  • Each Contact can have multiple Outreach actions (you might message them multiple times).
Tip
When you click a Pipeline entry and see “Contacts: 0” — that means no one has been profiled at that company yet. That’s a gap to fill.

Setup

One-Time Setup

6 tasks to do in the Notion UI · The engine created all databases, properties, and views programmatically, but these are better done by hand

1. Arrange the Page Layout ~2 min

The three databases are stacked vertically on the “Job Search Engine” page. You might want to:

  • Add a heading above each database (“Pipeline”, “Contacts”, “Outreach”) for visual separation
  • Add a divider between them
  • Optionally make the Pipeline database full-width and the other two side-by-side
  • Add a callout block at the top with your positioning compass or daily reminders

The engine can’t control page layout positioning — that’s a Notion UI operation.

2. Set Default Views ~1 min/db

Each database was created with a default “Table” view plus the custom views the engine added. Recommended defaults:

  • Pipeline: Set Pipeline Board as the default view (the one that opens first)
  • Contacts: Set All Contacts as the default
  • Outreach: Set Active Outreach as the default

To set default: Open the database → click the current view name → drag the view you want to the leftmost position. Notion shows the leftmost view by default.

3. Reorder View Tabs ~1 min

The views were created in the order the engine sent them, which may not be the order you want. Drag the view tabs left/right to your preferred order.

Suggested Pipeline order: Pipeline Board → Next Actions → Lane A → Lane B → Hot Targets → Calendar → Stale.

4. Customize Card Preview Properties Optional

On board views, each card shows a few properties. The engine set these (Company, Lane, Tier, Temperature, Next Action) but you might want to adjust — add Score, remove Lane, etc.

Click the “...” menu on any board view → Properties → toggle which properties show on cards.

5. Add Icons to Databases ~30 sec

The databases don’t have icons yet. Click the database title → Add Icon → pick an emoji:

  • Pipeline: 🎯 or 📊
  • Contacts: 👥 or 📇
  • Outreach: 📨 or ✉️
6. Empty Trash When ready

The test databases from capability testing are in your Notion Trash. When you’re satisfied the real databases work: Settings → Trash → delete the TEST_Pipeline and TEST_Contacts entries permanently.

Not urgent — they’re invisible unless you open Trash.

Reference

Key Design Decisions

Stage uses SELECT, not STATUS

The Notion API can create STATUS properties but can’t configure custom options. SELECT gives full engine control over the 10 pipeline stages with colors.

Tradeoff: No built-in group headers (Not Started / In Progress / Done). But individual stage columns on the Board view are actually better for a pipeline — each stage is its own Kanban column.

Relations are DUAL

Creating a relation on Contacts that points to Pipeline automatically creates a reverse “Contacts” relation on Pipeline. One DDL statement, both sides created.

This means clicking a Pipeline entry shows its linked Contacts, and clicking a Contact shows their linked Pipeline entries.

ROLLUP and FORMULA are engine-configured

Contact Count (rollup: count of linked contacts) and Days in Stage (formula: days since Date Added) are both created via DDL, not UI. They compute automatically — no manual configuration needed.

Markdown stays source of truth

Deep research profiles, evidence atoms, positioning documents, resumes, and audit logs live in the engine’s markdown files. Notion has the pipeline state (which stage, what’s next, who’s contacted).

Design Principle
When markdown and Notion disagree, markdown wins. The engine syncs from markdown → Notion, not the reverse — except for lightweight operator updates (temperature, notes, stage drags) which are reconciled at session start.
